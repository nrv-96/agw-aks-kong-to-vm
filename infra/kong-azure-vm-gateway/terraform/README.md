# Terraform - Kong/AKS infrastructure (8 modules)

Creates the foundation for the Kong/AKS stack. **Local state only** by request;
do not commit `terraform.tfstate`, `terraform.tfvars.json` or `vm-admin-password.txt`.

## Modules

| # | Module | Resources |
|---|---|---|
| 01 | `resource-group` | RG (create or reuse) |
| 02 | `network` | VNet, `snet-aks`, `snet-vm`, `snet-pe`, `snet-agw`, NSGs/rules, NAT gateway |
| 03 | `private-dns` | `internal.example.com`, A record `be` -> both VM IPs, VNet link |
| 04 | `vm` | 2 NICs, 2 Ubuntu 24.04 VMs, static IPs, no public IPs, Java 21 cloud-init, password auth, patch mode |
| 05 | `key-vault` | KV, RBAC authorization, public access, purge protection (no private endpoint) |
| 06 | `identity` | AKS workload UAMI + federated credential, AGW UAMI |
| 07 | `aks` | AKS Free tier, CNI Overlay, OIDC + workload identity, CSI provider, B4ms autoscale |
| 08 | `application-gateway` | Standard_v2, public IP, HTTPS listener, Kong backend, private-root trust, /health probe |

No observability, backup, WAF or private endpoints (by request).

## Naming and DNS

- Frontend: `fe.internal.example.com` (AGW public IP via Windows hosts file).
- Backend: `be.internal.example.com` -> `10.20.2.51`, `10.20.2.52` in the private zone.
- Kong listener and AGW frontend each use a separate `fe.internal.example.com` key/cert.
- `pairs-monitor-root-ca` signs both; the test PC must trust the root.

## Apply stages

1. **T1 - foundation** (`modules 01-07`): network, DNS, KV, AKS, identities, VMs.
2. **T2 - certificates and Kong**: run `certificates/` + Helm/CSI. Upload the CA:
   `./certificates/upload-ca-to-keyvault.sh --vault-name <kv>`; issue/install the VM
   certificates; install Kong. The separate `fe.internal.example.com` AGW frontend
   certificate and Kong listener certificate are produced by the pending Finding 8
   certificate workflow.
3. **T3 - AGW** (`module 08`): set `enable_application_gateway = true` and
   `agw_certificate_secret_id` after the AGW certificate exists in Key Vault.

## Commands

```bash
cd infra/kong-azure-vm-gateway
./scripts/terraform-config.sh          # generate terraform/terraform.tfvars.json from config.yaml
terraform -chdir=terraform init
terraform -chdir=terraform fmt -check
terraform -chdir=terraform validate
terraform -chdir=terraform plan
terraform -chdir=terraform apply        # requires explicit approval
```

After apply:

```bash
./scripts/sync-terraform-outputs.sh    # write tenant/KV/UAMI/IPs back into config.yaml
```

The VM admin password is generated by Terraform and written to
`terraform/vm-admin-password.txt` (0600, local state also contains it).

## Notes

- `kubernetes_version = "1.33"` matches KIC 3.5.14's client-go 0.33; verify the
  region still offers it before apply.
- AKS Free tier + a single `Standard_B4ms` node is intentionally low cost. Use the
  Helm `values-dev.yaml` profile (1 Kong replica); the prod 3-replica/PDB settings
  need at least 2-3 nodes.
- `aks_authorized_ip_ranges = []` leaves the public API unrestricted. Add your
  public IP/32 for a restricted API.
- `enable_application_gateway = false` until the AGW certificate exists.
